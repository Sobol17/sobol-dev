## Behavior

`/admin` redirects to `/admin/leads`. The list combines status and type filters, searches names and goals without case sensitivity, and paginates twenty records at a time. URL parameters preserve filters on refresh. Newer submissions appear first. Spam has its own tab and a one-action return to the active list.

The detail page displays submission fields, contacts, dates, attribution, spam score, IP hash and user agent. Status commands follow the owner-approved v5 transition matrix. Conditional updates reject a stale expected status. Repeating the current status leaves timestamps unchanged. Status changes refresh the requested list in the command response and do not publish notification jobs.

Notes use the authenticated session's author and remain append-only. Refreshing a detail preserves an unsaved note; opening another lead resets the form. Restoring spam preserves metadata, notes and the original spam score.

Each remote function checks authentication independently. Tests replay every function without a cookie and with a revoked session. SvelteKit 2.70.2 serializes an `HttpError(401)` as a remote error envelope over HTTP 200; the tests assert the envelope's status. Routes redirect anonymous visitors to login and reject malformed or missing detail ids with 404.

The existing CRM primitives, typography, surfaces and navigation remain. Shared rows render as a table on desktop and cards on narrow screens. The static demo retains its own existing navigation and read-only behavior. No database schema or migration changes are required.
