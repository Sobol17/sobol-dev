# A5: prepare a simple VPS deployment

The owner cancelled Telegram integration and requested preparation only on 10 October 2026. `tech.md` v6 replaces the earlier A5 notification requirements. Deployment uses Node 22, systemd and Caddy without Docker.

## Application

Submission persists the lead synchronously. The Telegram client, notifier interface, templates, outbox repository, queue, runner and scheduler are removed. Their environment settings and obsolete tests are removed too. Existing notification tables remain unchanged for database compatibility; application code never resumes historical jobs.

Adapter-node drains requests before the shutdown hook closes SQLite. Secrets remain compiled through static private environment imports. Only the non-secret database path accepts a runtime override. Browser tests build against a temporary path and start against a separately seeded persistent file, covering the deployment's database isolation.

## Deployment preparation

The [VPS runbook](../../deploy/README.md) covers prerequisites, initial setup, account creation, updates, rollback, snapshot restore and domain smoke checks. Release scripts build an exact clean-checkout commit as the service user, use a frozen lockfile, snapshot the live database before switching, atomically select the new release and verify health. A build failure keeps the active release; a failed health check attempts to restore the previous release.

The application binds to loopback behind Caddy. Service files restrict writes to the data directory, keep secrets and database files private and preserve the existing Origin/CSP protections. The backup timer creates read-only `VACUUM INTO` snapshots, verifies integrity and foreign keys and expires its own snapshots after fourteen days.
