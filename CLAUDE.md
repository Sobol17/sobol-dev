# CLAUDE.md

Проект `sobol-portfolio`: лендинг с формой заявки плюс админка портфолио. SvelteKit, TypeScript, Drizzle ORM, SQLite (`better-sqlite3`), adapter-node. Очередь своя, таблица `jobs` в том же файле БД.

## Читай первым

@tech.md — единственный источник истины. Прочитай его целиком перед первой правкой кода в сессии и подчиняйся дословно.

Там лежат: схема БД, контракты очереди, общие типы, список UI-примитивов, правила кода, конвенция коммитов, доктрина тестов, дорожная карта по стадиям.

Разработчик один, он же тимлид. Файлов ролей нет.

## Контракты не выдумывай

Не хватает типа, поля, таблицы, топика или пропса примитива — **СТОП**. Не пиши код с выдуманным контрактом и не расширяй `schema.ts` по ходу задачи.

Выдай блок и остановись:

```
CONTRACT GAP
Нужно: <что>
Зачем: <какой слайс и зачем>
Предлагаемая форма: <код контракта>
Затрагивает: <файлы>
Заглушка на время ожидания: <как продолжу без него>
```

`tech.md` правит только человек: аппендит контракт, бампает версию ядра, генерирует миграцию.

## Порядок работы

1. Каркас целиком, потом фичи. Фичу не начинать, пока чек-лист «каркас готов» (раздел 18 `tech.md`) не зелёный весь.
2. Один слайс за раз, один PR. Не вываливай приложение целиком, отдавай сфокусированный дифф.
3. Слайс повторяет раскладку эталонной вертикали `routes/(public)/lead/`. Сверяйся с ней, свою раскладку не изобретай.
4. Цикл: ветка → маленькие коммиты по ходу → PR → CI-гейт → мёрдж → автодеплой.

## Что делать всегда

- UI собирай из примитивов `$lib/ui`. Свою кнопку, поле или таблицу не пиши.
- Серверный код только под `$lib/server`. Секреты только через `$env/static/private` и `lib/server/config.ts`.
- Валидируй вход valibot-схемой из `$lib/schemas` на сервере, даже если клиент уже проверил.
- Сервисы и репозитории — классы с зависимостями в конструкторе. Внешний сервис — интерфейс плюс фейк.
- Помни про единственного писателя SQLite: длинную работу держи вне транзакции, в БД пиши результат. Публикацию джоба клади в ту же транзакцию, что и бизнес-данные.
- Каждый джоб идемпотентен. Раннер возвращает подвисшие джобы в работу, повторное исполнение штатно.
- Вычисляемое значение — `$derived`, не `$effect`. Общее реактивное состояние — класс в `.svelte.ts`.
- Пиши тесты из критериев приёмки задачи, не из своей реализации. На каждый джоб — тест идемпотентности. На стыке слайса — контрактный тест.
- Прогоняй `pnpm lint`, `svelte-check`, `vitest run` перед тем, как считать задачу готовой.

## Что не делать

- Не пиши миграции руками: `drizzle-kit generate` из `schema.ts`. Применённую миграцию не правь. SQLite часто пересоздаёт таблицу вместо `ALTER`, поэтому сгенерированный SQL читай глазами перед мёржем.
- Не отключай проверку Origin у SvelteKit и не ослабляй CSP ради удобства.
- Не клади `{@html}` без санитайза.
- Не прыгай на SvelteKit 3 `@next`. Стабильная линия 2.6x, версии `svelte` и `@sveltejs/kit` пиньтся точно.
- Не оставляй закомментированный код и `TODO` без номера задачи.
- Не расширяй объём задачи по своей инициативе. Идея за рамками слайса — отдельная строка в конце ответа, не код.

## Коммиты

Автор фиксирован, ставится один раз в репозитории:

```bash
git config user.name  "Sobol17"
git config user.email "sobolinskiii@mail.ru"
```

Формат всегда `type(scope): summary`, `type` из `feat|fix|test|refactor|chore|docs`, summary в императиве, со строчной, без точки, до 50 символов. Тело только чтобы объяснить *почему*.

Коммить сам по ходу работы, маленькими логическими шагами, а не одним коммитом в конце.

**Запрещено в коммитах, PR и коде:** трейлеры `Co-Authored-By` и `Co-authored-by: Claude`, строки `Generated with`, упоминания ассистента, эмодзи, любые подписи, которых не поставил автор. Коммит выглядит так, будто его написал человек, потому что автор один и он человек.
